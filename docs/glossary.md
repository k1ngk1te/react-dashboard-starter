# Glossary

Key terms and concepts used throughout this project and its documentation.

---

## Auth Cookie

An `httpOnly` cookie set by the Express server that stores the signed JWT. Because it is `httpOnly`, it cannot be read by JavaScript — only sent automatically by the browser on same-origin requests. Named by the `AUTH_KEY` environment variable.

---

## Auth Store

A plain pub-sub store (`src/store/listeners/auth.ts`) that holds the current auth state, user data, and CSRF token outside React. Components subscribe to it via `useSyncExternalStore` through the `useAuthContext()` hook. It is the single source of truth for whether the user is logged in. See [State Management](state-management.md).

---

## CheckAuth

The route wrapper (`src/layout/protections/check-auth.tsx`) that runs on app load to verify whether the user has a valid session. It calls `GET /api/auth/user/` and calls `authActions.login` or `authActions.logout` to update `authStore` based on the result.

---

## Container

A component in `src/containers/` that handles data-fetching and business logic for a page. Pages are kept thin (title, layout) while containers hold the actual functionality. Example: `src/containers/auth/login.tsx` handles the login form logic; `src/pages/index.tsx` just renders the container.

---

## CSRF Token

A random 32-byte hex string generated by the server to protect against Cross-Site Request Forgery attacks. Stored in an `httpOnly` cookie by the server and also returned in the `X-Csrf-Token` response header. The client reads it from the header and sends it back as a request header on every mutating request (`POST`). The server validates that the header value matches the cookie value before processing the request.

---

## Double-Submit Cookie Pattern

The CSRF protection strategy used in this project. The same token is stored in both a cookie (server-set, `httpOnly`) and sent in a request header (client-set). The server validates they match. Because third-party sites cannot read `httpOnly` cookies, they cannot forge a valid request.

---

## httpOnly Cookie

A browser cookie that cannot be accessed by JavaScript (`document.cookie`). It is automatically attached to same-origin HTTP requests but is invisible to client-side code. Used in this project for both the auth JWT and the CSRF token to prevent XSS attacks from stealing session credentials.

---

## HttpInstance

The Axios singleton (`src/utils/http/`) used for all client-side API calls. It manages the `Authorization` and `X-Csrf-Token` request headers and provides methods to update them as auth state changes: `current()`, `csrf(token)`, `login(token, csrf)`, `logout()`.

---

## JWT (JSON Web Token)

A signed token that encodes the user's credentials. Generated by the server on login using `jsonwebtoken` with the `SECRET_KEY` environment variable. The token is stored in the `httpOnly` auth cookie and decoded on every request to `GET /api/auth/user/` to restore the session.

---

## Query Tag

A React Query cache key used as the `queryKey` in all `useQuery` and `useMutation` calls. Keeping keys consistent makes cache invalidation predictable — calling `queryClient.invalidateQueries({ queryKey: ['auth'] })` clears all auth-related cached data.

---

## Rate Limiter

Express middleware (`express-rate-limit`) that restricts how many requests a single IP can make within a time window. Two limiters are configured: one for auth endpoints, one for general API routes. Both are configurable via environment variables. See [Environment Variables](environment-variables.md).

---

## Serializer

A function in `src/server/serializers/` that transforms a raw API response into the shape expected by the application. Used to decouple the app's internal data types from the external API's response format. When the external API changes, only the serializer needs to be updated.

---

## Serverless Function

The Netlify deployment entry point (`netlify/functions/serverless.ts`). It wraps the same Express router used by the self-hosted server in a `serverless-http` adapter, allowing it to run as an AWS Lambda function on Netlify's infrastructure.

---

## SplashScreen

A full-screen loading spinner (`src/components/common/splash-screen.tsx`) displayed while `CheckAuth` is verifying the session or while the `Authenticated` / `NotAuthenticated` wrappers are determining which layout to render.

---

## TEST_MODE

An environment variable (`TEST_MODE=1`) that enables debug behaviour on the server — raw error messages are returned in API responses and the client IP is exposed in the health endpoint. Should always be `0` in production.

---

## tsx

The TypeScript executor used to run `.ts` files directly in Node.js without a compilation step. Used in `npm run dev:node` (`nodemon --exec tsx server/index.ts`) for development. Not used in production — the server is compiled to plain JS by `tsc` and run with `node`.

---

## TRUST_PROXY

An Express setting that controls how many proxy hops to trust when reading the client IP from `X-Forwarded-For` headers. Must be set to `1` (or higher) when running behind Nginx or a load balancer, otherwise rate limiting will apply to the proxy IP instead of the real client IP.
